# ADR 0005：可恢复配置提交与不确定结果处理

| 属性 | 内容 |
|---|---|
| 状态 | M1 已接受，待实现 |
| 日期 | 2026-07-19 |
| 范围 | M1 配置写盘、恢复、Repair 和提交并发 |
| 配置模型 | [`0004-versioned-native-configuration-and-explicit-save.md`](0004-versioned-native-configuration-and-explicit-save.md) |
| 里程碑合同 | [`M1-processing-chain-foundation.md`](../milestones/M1-processing-chain-foundation.md) |

## 背景

配置写盘和实时链发布属于两个不能组成跨域原子事务的系统。主文件原子替换成功后，最终
目录同步仍可能失败；此时当前进程通常能读到新文件，但崩溃或断电后的磁盘结果可能是完整
新代次或完整旧代次。简单回滚听感、覆盖重试或把 `previous` 当作第二事实来源，都无法
准确表达该状态。

音效总开关又要求先即时改变当前会话听感，再持久化恢复值。保存节点草稿、切换总开关、
Stop 和桥接换代可能交错，因此必须明确提交线性化、恢复所有权和失败终态。

## 决策

1. `config.json` 表示期望状态；`config.previous.json` 只保存上一份完整主文件，用于主文件
   缺失或损坏时恢复，不是并列可写来源。
2. 同目录临时文件完整写入并同步后，按里程碑规定的顺序原子替换 `previous` 和主文件，
   并同步目录。首次创建和 Repair 先建立可恢复的完整 `previous`，再建立主文件。
3. 主文件替换前的确定失败不改变已保存状态；保留草稿或进入 Recovery，并允许显式 Repair。
4. 主文件已经替换但最终目录同步失败时，一律进入“持久化结果不确定”：冻结编辑、Save、
   音效总开关和 Start，不接收新候选，也不后台重试。用户只能 Retry 同一代次、Exit 或
   Cancel；Stop 始终可用。
5. Recovery 有完整 `previous` 时继续按该恢复链处理；完全没有有效配置时使用透明安全链。
   Repair 成功前不建立正常已保存基线，并禁用音效总开关。
6. 音效总开关通过独立实时通道即时生效。普通持久化失败不回滚当前听感、不后台重试；
   后续用户持久化操作再尝试保存最新状态。
7. Save 开始时捕获不可变候选。节点编辑只推进草稿修订，不取消已接纳提交；Stop 或桥接
   换代只让 Prepared 对象失效，不取消写盘。每个已接纳提交必须以成功、明确失败或结果
   不确定结束。
8. 提交队列串行执行。当前 Save 及其音效总开关后继写入到达终态前禁用第二次 Save；
   Stop 后 Start 等待提交终态，再从实际成功保存的主配置构建。

## 理由

| 关注点 | 采用方案的收益 |
|---|---|
| 崩溃一致性 | 主文件和 previous 始终以完整代次恢复，不把半文件当配置 |
| 事实诚实 | 无法证明目录持久化结果时明确进入受限状态，不伪报成功或失败 |
| 听感连续性 | 音效总开关保存失败不会突然回滚用户刚选择的听感 |
| 生命周期 | Stop 始终优先且不丢提交；Start 只使用有确定终态的配置 |
| 并发 | 不可变候选和串行提交让主文件、previous 与后继意图顺序唯一 |
| 可恢复性 | Repair 不覆盖唯一有效 previous，完全损坏时仍保持透明安全输出 |

## 备选方案

| 方案 | 不采用原因 |
|---|---|
| 单文件直接覆盖 | 可能留下截断或损坏配置，没有上一完整代次 |
| 把文件写盘和实时发布声明为原子事务 | 文件系统与音频回调之间不存在该原子性 |
| 最终目录同步失败后自动重试或接收新候选 | 会混淆未知磁盘代次和新用户意图 |
| 总开关保存失败后回滚听感 | 会产生用户未请求的即时声音变化 |
| Stop 取消在途 Save | 会静默丢失已接纳用户命令 |
| 把 previous 当作第二配置源 | 会产生两个可写事实来源和不唯一恢复基线 |

## 后果

- 控制层需要分别跟踪草稿修订、提交代次和桥接代次；
- UI 必须呈现 Recovery、保存中、保存失败、已保存待启动和持久化结果不确定；
- 应用退出必须等待在途提交到达终态，并在不确定状态使用专用退出流程；
- 故障注入必须覆盖每个文件同步、重命名和目录同步边界；
- M4 的设备与系统服务自动恢复不得改变本 ADR 的配置完整性语义。

## 重新评估条件

- macOS 目标文件系统或同步 API 无法提供所需原子替换与持久化语义；
- 产品引入云同步、多配置库或多进程写入；
- 实测证明双文件协议无法满足性能或可靠性目标；
- 产品要求后台自动重试或跨崩溃恢复未保存用户意图。
