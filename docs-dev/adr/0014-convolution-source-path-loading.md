# ADR-0014：Convolution 外部源路径与生效时加载

- 状态：部分被 ADR-0017 取代；source-path 生命周期仍有效
- 日期：2026-07-28
- 关联：ADR-0004、ADR-0009、ADR-0010、ADR-0017

## 后续修订

2026-07-30，ADR-0017 取代本文第 3、5、6 项中的 IR SRC、文件大小/时长、tap 总量和采样率失败
语义。当前仍在每次生效时读取源路径，但不重采样、不设置样本数配额；采样率不匹配只旁路所属
节点。IR 时长性能警告已移除（2026-08-04）。本文的 schema v8 sourcePath、无 sidecar、每次生效重读、
Prepared 持有和节点级资源恢复语义继续有效。

## 背景

schema v4-v7 把所选 WAV 复制到应用数据目录，以 `storageID`、SHA-256 和导入时 metadata
引用不可变 sidecar。复制发生在节点编辑事务之前；后续编辑失败会留下配置不可达的孤儿文件，
同时应用还要承担副本清理、替换和恢复责任。用户要求改为 EqualizerAPO 风格的源路径引用：
不复制，文件在每次配置真正生效时重新打开、校验和加载，加载后的 taps 由 Prepared 持有。

## 决策

1. 配置与 typed clipboard 升级到 schema v8。新 Convolution 引用只持久化标准化绝对
   `sourcePath`，不持久化音频 bytes、应用管理的 storage ID、固定 hash 或导入时 metadata。
2. Add/Replace 只记录文件选择器返回的路径，不读取、解码或复制文件。扩展名过滤只属于 UI
   辅助，不构成有效性校验。
3. Start、运行中 Save 发布、路由重建和输出格式恢复在控制工作路径中重新打开源文件，一次性
   读取、校验、解码并按当前输出采样率重采样。音频 callback 不访问文件系统。
4. 读取后的 taps 由新 Prepared 持有；旧 Prepared 按现有退休协议释放。第一版不建立跨生效
   周期的长期缓存，避免文件原地替换、symlink 或卷重挂载造成陈旧结果。
5. 文件不存在、不可读、过大、格式/样本/时长非法以及 IR 声道数与当前有效作用域不匹配时，
   只旁路对应 Convolution 并产生归属于该节点的 diagnostic。配置中的 `isEnabled` 保持用户意图，
   不被自动改为 false；下一次生效会重新尝试并可自动恢复。
6. schema/节点结构错误和全局 stage/tap/Prepared 容量超限仍整批拒绝，不能由 Builder 自行选择
   丢弃哪个合法节点。
7. schema v4-v7 没有保存原始源路径，因此迁移时把旧 `storageID` 映射为现有 Application
   Support sidecar 的绝对路径并规范写出 v8。迁移不删除历史 sidecar；用户 Replace 后的新引用
   才指向外部路径。新版本不再创建 sidecar。
8. 配置复制到其他机器时路径可能不可用；外部文件内容变化会在下一次生效时改变结果。这是所选
   路径模型的明确产品语义，UI 必须显示路径和有效旁路原因。

## 拒绝的替代方案

- **修补 sidecar rollback 与垃圾回收**：保留了双重资源生命周期，复杂度高于根因修复。
- **选择文件时先校验再保存**：产生重复 IO，并不能保证真正生效时文件仍相同。
- **资源失败时持久化关闭节点**：把暂时的卷或权限故障写进用户配置，破坏恢复意图。
- **资源失败时拒绝整个处理链**：一个外部文件会阻断其他独立处理器和应用启动。
- **跨 Save 长期缓存**：必须建立可靠的文件身份与失效协议，违背每次生效重新加载的契约。

## 结果

Convolution 的持久事实来源变为用户选择的路径，孤儿副本问题不再产生。运行时继续只消费不可变
Prepared 内存；外部资源可用性通过 diagnostics 显式呈现，并在每次生效边界重新判定。
